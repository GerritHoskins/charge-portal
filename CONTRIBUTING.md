# Contributing

Short on purpose. The rules that matter are enforced by `npm run check`, not by this page.

## Daily loop

```bash
npm run dev            # legacy stand-in :8080 + Nuxt :3000
npm run check          # lint, typecheck, tokens, migration inventory, unit + coverage, E2E, bundle budget
npm run hooks:install  # optional: pre-commit runs lint + typecheck
```

If a dev server is already running, E2E can use other ports:
`NUXT_IGNORE_LOCK=1 E2E_APP_PORT=3100 E2E_LEGACY_PORT=8180 npx playwright test`.

## Standards (and what enforces them)

| Standard | Rule | Enforced by |
|---|---|---|
| Tests first | A behaviour change starts with a failing test | review, `AGENTS.md`, coverage floor in `vitest.config.ts` |
| Contracts | Legacy data is only read through `shared/contracts/*`; a new endpoint needs a schema and a test with an **invalid** case | review, `tests/e2e/contract.spec.ts` |
| Accessibility | New routes and design-system components need an axe check; meaning never by colour alone; forms follow the ADR 0003 pattern | `tests/e2e/*.spec.ts`, `storybook.spec.ts` |
| Design system | Pages compose `app/components/ds/*` and use `var(--…)` tokens only. DS components do not use Nuxt auto-imports or `useI18n` | ESLint `no-restricted-globals`, Storybook |
| Tokens | Edit `tokens/tokens.json`, then `npm run tokens`. Never edit `tokens.css` | `npm run tokens -- --check`, contrast unit tests |
| Copy | No visible string in a page; add it to **both** `i18n/locales/*.json` | `tests/unit/i18n-catalogues.test.ts` |
| Code quality | Strict TypeScript, no `any`, no warnings | `npm run lint` (`--max-warnings 0`), `npm run typecheck` |
| Migration | Every page is in `docs/migration-routes.json`; a migrated route has an ADR reference | `npm run migration:status -- --check` |
| Decisions | A change to a boundary (auth, rollout, data contract) gets an ADR, including its user/business value and its limits | review |

## Definition of done for a migrated route

1. A page under `app/pages/` built from design-system components; strings in both catalogues.
2. Data through a BFF handler that parses with a `shared/contracts` schema (invalid case tested). Outage or drift is a 502, never an empty page.
3. An axe E2E check (WCAG 2.2 AA tags) and, for forms, a keyboard-only test.
4. Server-side auth: the route is under `/portal` or `/api`, so `server/middleware/auth.ts` guards it.
5. A rollback target: either a legacy fallback page (`legacy/pages.mjs`, and `legacy-php`) or a documented decision that there is none.
6. An entry in `docs/migration-routes.json` and, if it changes a decision, an ADR.
7. `docs/accessibility-checks.md` updated if the route introduces a new interaction pattern.

See `docs/migration-playbook.md` for the order to do this in.

## Code review

Reviews are about the change, not the person. Say what you observed and why it matters, offer an alternative when
you can, and mark what is a blocker versus a preference ("nit:"). Authors answer every comment, even with "done".
Anything generated by an AI assistant is a draft the author must be able to explain (`AGENTS.md`).
